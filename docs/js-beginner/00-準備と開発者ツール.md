# 第0章 準備と開発者ツール

## この章のゴール

- 教材を進めるための環境を整える
- ブラウザの開発者ツール (DevTools) を開き、Console で JavaScript を実行できるようになる
- `console.log` で値を確認する習慣を身につける

---

## 0-1. 必要なもの

| 必要なもの | 補足 |
| --- | --- |
| モダンなブラウザ | Google Chrome / Microsoft Edge / Firefox / Safari のいずれか。この教材では Chrome を前提に説明します |
| テキストエディタ | [Visual Studio Code](https://code.visualstudio.com/) を推奨。無料です |
| このリポジトリ | `index.html` などのファイル一式 |

**Node.js のインストールは不要です。** このアプリはブラウザだけで完結しています。
サーバーも立てません。`index.html` をダブルクリックするだけです。

---

## 0-2. アプリを動かしてみる

1. エクスプローラー (Mac なら Finder) でリポジトリのフォルダを開く
2. `index.html` をダブルクリック
3. ブラウザに「体調記録」という画面が出れば成功

出てきたら、次のことを **必ず全部試してください**。この後の章で「どのコードがこの動きを作っているか」を追いかけます。

- [ ] 今日の日付で、5項目のプルダウンと睡眠時間を入力して「保存する」を押す
- [ ] もう一度同じ日付を選ぶ → ボタンが「上書き保存する」に変わることを確認
- [ ] 日付を昨日に変えて、もう1件保存する
- [ ] さらに数日分保存して、画面に折れ線グラフが出ることを確認 (2件以上で表示されます)
- [ ] 一覧の「編集」を押す → フォームにその日のデータが読み込まれる
- [ ] 「削除」を押す → 確認ダイアログが出る
- [ ] 「Excelで書き出し」を押す → `.xlsx` ファイルがダウンロードされる
- [ ] ブラウザを一度閉じて開き直す → データが消えていないことを確認

最後の項目が特に重要です。**なぜリロードしてもデータが残るのか**、第9章で扱います。

---

## 0-3. 開発者ツールを開く

プログラマーが一番よく使う道具です。必ず開けるようにしてください。

| OS / ブラウザ | ショートカット |
| --- | --- |
| Windows (Chrome / Edge / Firefox) | `F12` または `Ctrl` + `Shift` + `I` |
| Mac (Chrome / Edge / Firefox) | `Command` + `Option` + `I` |
| Mac (Safari) | 先に「環境設定 → 詳細 → Web開発者用の機能を表示」を有効化してから `Command` + `Option` + `I` |

開いたら上部のタブを確認します。この教材でよく使うのは次の3つです。

- **Console (コンソール)** … JavaScript を直接実行したり、エラーメッセージを読んだりする場所
- **Elements (要素)** … 今ブラウザが持っている HTML を見る場所
- **Application (アプリケーション)** … localStorage に保存されているデータを覗く場所 (第9章で使います)

---

## 0-4. Console で JavaScript を実行してみる

Console タブを開き、`>` の横に次を打ち込んで `Enter` を押してください。

```js
1 + 1
```

`2` と表示されれば成功です。Console は **電卓であり、実験室** です。
文法に迷ったら本を調べる前に、まず Console で試してください。

いくつか試してみましょう。

```js
"体調" + "記録"          // "体調記録"
10 / 3                   // 3.3333333333333335
[1, 2, 3].length         // 3
new Date().getFullYear() // 2026 (今年)
```

### 体調記録アプリの中身を覗く

アプリのページを開いた状態で、Console に次を打ってみてください。

```js
localStorage.getItem("taichou-kiroku:v1")
```

先ほど保存した記録が、長い文字列として表示されるはずです。
これが「ブラウザを閉じてもデータが消えない」正体です。詳しくは第9章で。

## 0-5. `console.log` ― 一番大事なデバッグ手段

プログラムが思った通りに動かないとき、初学者がまずやるべきことは
**「その時点で変数に何が入っているかを表示する」** ことです。それが `console.log()` です。

```js
const name = "たろう";
console.log(name);          // たろう
console.log("name は", name); // name は たろう
```

`app.js` の中でも、うまくいかない可能性のある場所で使われています。

```js
// app.js より
} catch (e) {
  console.warn("保存データの読み込みに失敗しました", e);
  return {};
}
```

`console.warn` は `console.log` の警告版で、Console 上で黄色く目立つように表示されます。
仲間には `console.error` (赤色) もあります。

### 実験してみよう

`app.js` の先頭あたり (`"use strict";` の次の行) に、次の1行を追加して保存し、ブラウザをリロードしてください。

```js
console.log("app.js が読み込まれました！");
```

Console にメッセージが出たら、**あなたの書いた JavaScript が実際に動いた** ということです。
確認できたら、この行は消しておきましょう。

## 0-6. エラーメッセージを恐れない

コードを間違えると Console に赤い文字が出ます。これは敵ではなく **一番親切なヒント** です。

```
Uncaught TypeError: Cannot read properties of null (reading 'value')
    at app.js:123
```

読み方は次の通りです。

| 部分 | 意味 |
| --- | --- |
| `TypeError` | エラーの種類 (型の間違い) |
| `Cannot read properties of null (reading 'value')` | `null` に対して `.value` を読もうとした |
| `at app.js:123` | `app.js` の **123行目** で起きた |

つまり「123行目で、あるはずのものが `null` だった」と教えてくれています。
エラーが出たら、まず **行番号を見て、その行を開く**。これが鉄則です。

初学者がよく出会うエラーを挙げておきます。

| エラー | よくある原因 |
| --- | --- |
| `Uncaught SyntaxError: Unexpected token` | カッコや引用符の閉じ忘れ |
| `Uncaught ReferenceError: xxx is not defined` | 変数名のタイプミス、定義前に使っている |
| `Uncaught TypeError: xxx is not a function` | 関数名のタイプミス、関数でないものを `()` で呼んだ |
| `Cannot read properties of null` | `getElementById` が要素を見つけられなかった (id のスペルミスなど) |

## やってみよう

1. Console で `todayString` と打って `Enter` を押してください。エラーになりますか？ なぜでしょう。
   (ヒント: `app.js` の中身は `(function () { ... })();` で囲まれています。理由は第12章で扱います)

   なぜ結果が違うのでしょうか。第2章で答え合わせをします。
3. わざとエラーを出してみましょう。Console で `document.getElementById("sonzai-shinai-id").value` と打ち、
   どんなエラーメッセージが出るか読んでみてください。
