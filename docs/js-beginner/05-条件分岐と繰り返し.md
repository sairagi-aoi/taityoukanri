# 第5章 条件分岐と繰り返し

## この章のゴール

- `if` / `else` と比較演算子・論理演算子を使いこなす
- 三項演算子 `? :` が読める・書ける
- `for...of` / `while` / `for` を使い分けられる
- 「falsy な値」の落とし穴を理解する

---

## 5-1. `if` ― 条件によって処理を変える

```js
if (条件) {
  // 条件が true のときに実行
} else {
  // そうでないときに実行
}
```

`app.js` から実例を見ましょう。日付を変えたとき、その日の記録があるかどうかで処理が分かれます。

```js
if (entries[dateInput.value]) {
  fillForm(dateInput.value);   // 記録があるので、フォームに読み込む
} else {
  resetForm(true);             // 記録がないので、空にする
}
```

`else if` で条件を連ねることもできます。

```js
if (!hasAny) {
  emptyMsg.textContent = "まだ記録がありません。フォームから今日の記録を保存しましょう。";
} else if (dates.length === 0) {
  emptyMsg.textContent = "この月の記録はありません。月を変えるか「すべての月」を選んでください。";
  emptyMsg.hidden = false;
}
```

「1件も記録がない」と「今月の記録だけがない」で、案内文を変える気配りです。
**エラーや空状態のメッセージを状況に合わせて変える** のは、良いアプリの条件のひとつです。

## 5-2. 比較演算子

| 演算子 | 意味 | 例 |
| --- | --- | --- |
| `===` | 等しい (型も含めて) | `s === null` |
| `!==` | 等しくない | `raw.memo !== ""` |
| `<` `>` `<=` `>=` | 大小 | `n < 1`, `hours > 24` |

第2章で触れたとおり、**`==` / `!=` ではなく `===` / `!==` を使います。**

文字列にも `<` `>` が使えます。辞書順の比較になります。

```js
"2026-09-15" < "2026-09-16"   // true
"apple" < "banana"            // true
```

`app.js` はこれを日付の並べ替えに利用しています (第2章参照)。

## 5-3. 論理演算子 `&&` `||` `!`

| 演算子 | 意味 | 読み方 |
| --- | --- | --- |
| `&&` | かつ (両方が true) | AND |
| `\|\|` | または (どちらかが true) | OR |
| `!` | 否定 | NOT |

`scoreValue` の条件を分解してみましょう。

```js
if (!Number.isInteger(n) || n < 1 || n > 5) return null;
```

「**整数でない** または **1未満** または **5より大きい**」なら不正、という意味です。
つまり「1〜5の整数」以外はすべて弾いています。

`parseSleepHours` はもっと丁寧です。

```js
function parseSleepHours(v) {
  if (v === null || v === undefined || v === "") return null;   // 空っぽを弾く
  const raw = String(v).trim();
  if (!/^\d+(\.\d+)?$/.test(raw)) return null;                  // 数字の形でないものを弾く
  const hours = Number(raw);
  if (!Number.isFinite(hours) || hours < 0 || hours > 24) return null;  // 範囲外を弾く
  return Math.round(hours * 100) / 100;
}
```

3段階のチェックがすべて `||` で繋がれています。
**「不正なパターンを1つずつ列挙して、どれかに当たったら弾く」** という書き方です。

最後の `Math.round(hours * 100) / 100` は「小数第2位で四捨五入」のイディオムです。
`7.567` → `756.7` → `757` → `7.57`。小数の誤差を持ち込まないための処理です。

### ショートサーキット (短絡評価)

`&&` と `||` には、知っておくべき性質があります。

```js
a && b   // a が false なら、b は評価されない (a をそのまま返す)
a || b   // a が true なら、b は評価されない (a をそのまま返す)
```

これを利用して、`||` は **「既定値」** を書くのによく使われます。

```js
memoSpan.textContent = e.memo;
// ...
(e.memo || "").slice(0, MEMO_MAX)   // memo が undefined でも "" として扱う
```

`e.memo` が `undefined` だと `.slice` でエラーになりますが、
`(e.memo || "")` と書けば `undefined` のときは `""` が使われるので安全です。

同様に `&&` は **「あるときだけ実行」** に使えます。

```js
const opt = OPTIONS[field].find((o) => o.value === Number(value));
return opt ? opt.label : "";
```

## 5-4. falsy な値 ― 一番の落とし穴

`if ( )` の中には、`true` / `false` 以外の値も書けます。
JavaScript は「それっぽく」真偽に変換します。

**falsy (false 扱いになる値) は、次の6つだけです。**

```
false, 0, "" (空文字), null, undefined, NaN
```

**これ以外はすべて truthy** です。特に注意すべきなのは:

```js
if ([])  { /* 実行される！ 空配列は truthy */ }
if ({})  { /* 実行される！ 空オブジェクトも truthy */ }
if ("0") { /* 実行される！ 文字列の "0" は truthy */ }
```

`app.js` では truthy / falsy がうまく活用されています。

```js
if (!raw) return {};                  // raw が null / undefined / "" なら
const hasToday = Boolean(entries[today]);   // 記録があれば true、なければ (undefined なので) false
if (!Object.keys(entries).length) {   // 件数が 0 なら
if (e.memo) { /* メモが空文字でないなら */ }
```

`Boolean(...)` は明示的に真偽値へ変換する書き方です。
`entries[today]` はオブジェクトか `undefined` なので、`Boolean` を通すと `true` / `false` になります。

### 落とし穴の例

```js
const count = 0;
if (count) {
  console.log("記録があります");   // 実行されない！ 0 は falsy
}
```

「0件」と「値が入っていない」を区別したいときは、はっきり書く必要があります。

```js
if (count > 0) { ... }
if (value !== undefined) { ... }
```

`app.js` でも、スコアの検査に `if (!s)` ではなく `if (s === null)` を使っています。
なぜでしょうか。**スコアが `0` の可能性を考えてみてください**。

実際には `scoreValue` は 1〜5 しか返さないので `0` にはなりませんが、
`=== null` と明示することで「null チェックである」という意図がはっきりします。

## 5-5. 三項演算子 `条件 ? A : B`

`if` の短縮形です。**値を返す** のが `if` との違いです。

```js
条件 ? 条件がtrueのときの値 : falseのときの値
```

`app.js` にたくさん出てきます。

```js
return opt ? opt.label : "";

saveBtn.textContent = exists ? "上書き保存する" : "保存する";

streakEl.textContent = streak > 0 ? `連続 ${streak} 日` : "連続記録なし";

flash(
  existed
    ? `${formatDateJa(entry.date)} の記録を上書きしました。`
    : `${formatDateJa(entry.date)} の記録を保存しました。`
);
```

`if` で書くとこうなります。

```js
if (exists) {
  saveBtn.textContent = "上書き保存する";
} else {
  saveBtn.textContent = "保存する";
}
```

4行が1行になり、しかも「`saveBtn.textContent` を決めている」という主題が読み取りやすくなります。

### 入れ子の三項演算子

`app.js` には少し難しい例もあります。

```js
countEl.textContent = total
  ? listMonthFilter
    ? `${dates.length}件 / 全${total}件`
    : `${total}件`
  : "";
```

分解して読みます。

```
total が 0 (falsy) なら            → ""
total が 1以上で
    listMonthFilter がある (月を絞っている) → "3件 / 全12件"
    listMonthFilter が "" (全件表示)        → "12件"
```

インデントで構造を示しているので読めますが、これ以上深くすると読めなくなります。
**三項演算子の入れ子は2段まで** が実用的な目安です。

もう1つの入れ子の例が、ソートの比較関数です。

```js
.sort((a, b) => (a < b ? 1 : a > b ? -1 : 0))
```

`a < b` なら `1`、そうでなくて `a > b` なら `-1`、どちらでもない (等しい) なら `0`。
これで降順 (新しい日付が先) になります。第10章で詳しく説明します。

## 5-6. 繰り返し ― `for...of`

配列の要素を1つずつ処理する、いちばん読みやすい書き方です。

```js
for (const field of SCORE_FIELDS) {
  const select = $(SELECT_IDS[field]);
  if (select.value === "" || !isValidSelectValue(field, select.value)) {
    missing.push(FIELD_LABELS[field]);
    setFieldInvalid(select, true);
  }
}
```

`SCORE_FIELDS` の中身が順に `field` に入り、5回ループします。
**インデックス (番号) を書かなくてよい** のが `for...of` の利点です。

配列以外にも使えます。

```js
for (const date of dates) { ... }                  // 配列
for (const field of Object.keys(OPTIONS)) { ... }  // オブジェクトのキーの配列
for (const tr of tbody.querySelectorAll("tr")) { ... }  // DOM の要素リスト
for (const part of [...localParts, ...centralParts, eocd]) { ... }  // xlsx.js より
```

## 5-7. `while` ― 条件が成り立つ間ずっと

回数が事前に分からないときは `while` です。

```js
function computeStreak() {
  let streak = 0;
  let day = todayString();
  while (entries[day]) {      // その日の記録がある間、ずっと
    streak += 1;
    day = addDays(day, -1);   // 1日前へ
  }
  return streak;
}
```

「連続何日記録したか」は、実際に数えてみないと分かりません。だから `while` が適しています。

> **無限ループに注意**: `while` は、条件が `false` にならないと永久に回り続けます。
> この関数では `day = addDays(day, -1)` で必ず日付が過去に移動するので、
> いつか記録のない日に当たって止まります。**「条件を変化させる処理」を必ず入れてください。**
> もし `day = addDays(day, -1)` を書き忘れたら、ブラウザが固まります。

`xlsx.js` にも `while` があります。

```js
function colName(idx) {
  // 0 -> A, 25 -> Z, 26 -> AA
  let s = "";
  idx += 1;
  while (idx > 0) {
    const m = (idx - 1) % 26;
    s = String.fromCharCode(65 + m) + s;
    idx = Math.floor((idx - 1) / 26);
  }
  return s;
}
```

Excel の列名 (A, B, ..., Z, AA, AB, ...) を作る処理です。26進数の変換なので、
何回割ればよいかは数値によって変わります。だから `while` です。

## 5-8. `for` ― 回数が決まっているとき

```js
for (let level = 1; level <= 5; level++) {
  const y = yPos(level);
  const line = document.createElementNS("http://www.w3.org/2000/svg", "line");
  // ... 目盛り線を1本描く
  trendsSvg.appendChild(line);
}
```

グラフの目盛り線をレベル1〜5の5本描いています。

```js
for (初期化; 続ける条件; 毎回の処理) { }
```

`let level = 1` で始め、`level <= 5` の間続け、毎回 `level++` (1増やす)。
**ここは `let` でなければなりません**。毎回値が変わるからです。

`for...of` と違い、**1から始めたい・2つずつ飛ばしたい** といった細かい制御ができます。
ただし今どきは、配列を回すなら `for...of` のほうが読みやすいので、
`for` を使うのは「数値の範囲を回す」ときに限ると考えてよいでしょう。

### ループを途中で抜ける・飛ばす

```js
for (const date of dates) {
  const e = entries[date];
  if (!e) continue;   // データが無ければ、この回はスキップして次へ
  // ...
}
```

- `continue` … この回だけ飛ばして次へ
- `break` … ループそのものを終了する

## まとめ

- 条件分岐は `if` / `else if` / `else`。比較は `===`、論理は `&&` `||` `!`
- **falsy は `false`, `0`, `""`, `null`, `undefined`, `NaN` の6つだけ**。空配列 `[]` は truthy
- `||` は既定値の指定に使える (`(e.memo || "")`)
- 三項演算子 `条件 ? A : B` は値を返す `if`。入れ子は2段まで
- 配列を回すなら `for...of`、回数が決まっているなら `for`、回数不明なら `while`
- `while` には必ず「条件を変化させる処理」を入れる
