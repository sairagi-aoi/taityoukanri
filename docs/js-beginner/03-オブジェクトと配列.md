# 第3章 オブジェクトと配列 ― データの設計

## この章のゴール

- オブジェクトと配列の違いと使い分けが分かる
- `OPTIONS` の入れ子構造を読み解ける
- `entries` が「配列ではなくオブジェクト」で設計されている理由を説明できる
- 分割代入・スプレッド構文が読める

---

## 3-1. 配列 ― 順番のあるリスト

複数の値を **順番に** 並べたものが配列です。`[ ]` で作ります。

```js
const SCORE_FIELDS = ["condition", "mental", "appetite", "motivation", "sleepQuality"];
```

これは「5つの評価項目の名前リスト」です。取り出すときは **0から数えた番号 (インデックス)** を使います。

```js
SCORE_FIELDS[0]       // "condition"
SCORE_FIELDS[4]       // "sleepQuality"
SCORE_FIELDS.length   // 5
SCORE_FIELDS[5]       // undefined  ← 存在しない番号はエラーにならず undefined
```

**0から始まる**のが最初の関門です。`length` は 5 なのに、最後の番号は 4 です。

### なぜこの配列があるのか

`SCORE_FIELDS` があると、「5つの項目すべてに同じ処理をする」が1回で書けます。

```js
// app.js より
for (const field of SCORE_FIELDS) {
  const s = scoreValue(raw[field]);
  if (s === null) return null;
  scores[field] = s;
}
```

もしこの配列がなければ、`condition`、`mental`、`appetite`… と同じコードを5回書くことになります。
項目を1つ増やしたくなったら、5回書かれたコードを全部探して直すことに。

配列にまとめておけば、**`SCORE_FIELDS` に1語足すだけ** で全ての処理が新項目に対応します。
`app.js` の中で `SCORE_FIELDS` は6か所に登場します。1語の追加が、それらすべてに効くわけです。

## 3-2. オブジェクト ― 名前のついた箱の集まり

順番ではなく **名前 (キー) で** 値を取り出したいときはオブジェクトです。`{ }` で作ります。

```js
const entry = {
  date: "2026-09-16",
  condition: 5,
  mental: 4,
  appetite: 3,
  motivation: 4,
  sleepHours: 7.5,
  sleepQuality: 4,
  memo: "よく眠れた",
  updatedAt: "2026-09-16T10:30:00.000Z",
};
```

これが **1日分の記録** です。取り出し方は2通りあります。

```js
entry.condition       // 5   ← ドット記法。キーが決まっているとき
entry["condition"]    // 5   ← ブラケット記法。同じ結果

const field = "mental";
entry[field]          // 4   ← キーが変数のときはブラケット記法しか使えない
entry.field           // undefined ← "field" というキーを探してしまう
```

この違いは重要です。先ほどのループを見返してください。

```js
for (const field of SCORE_FIELDS) {
  const s = scoreValue(raw[field]);   // ← 変数なのでブラケット記法
```

`field` には順に `"condition"`, `"mental"`, … が入るので、`raw[field]` でないと動きません。

### オブジェクトと配列の使い分け

| | 配列 `[ ]` | オブジェクト `{ }` |
| --- | --- | --- |
| 取り出し方 | 番号 `list[0]` | 名前 `obj.date` |
| 向いている用途 | 同じ種類のものが並ぶ | 性質の違う値を1セットにする |
| 例 | 記録の一覧、選択肢のリスト | 1日分の記録、設定のまとまり |

## 3-3. 入れ子構造 ― `OPTIONS` を読み解く

実際のデータは、配列とオブジェクトが組み合わさった入れ子になります。
`app.js` の `OPTIONS` がその典型です。

```js
const OPTIONS = {
  condition: [
    { value: 5, label: "とても良い" },
    { value: 4, label: "良い" },
    { value: 3, label: "普通" },
    { value: 2, label: "やや悪い" },
    { value: 1, label: "悪い" },
  ],
  mental: [
    { value: 5, label: "とても安定" },
    // ...
  ],
  // appetite, motivation, sleepQuality も同様
};
```

外から順に読みます。

1. `OPTIONS` は **オブジェクト** (`{` で始まる)。キーは `condition` / `mental` / … の5つ
2. `OPTIONS.condition` は **配列** (`[` で始まる)。5個の要素が入っている
3. 配列の1つ1つは **オブジェクト**。`value` と `label` の2つのキーを持つ

だから、こう取り出せます。

```js
OPTIONS.condition            // 配列 (5要素)
OPTIONS.condition[0]         // { value: 5, label: "とても良い" }
OPTIONS.condition[0].label   // "とても良い"
OPTIONS.condition[0].value   // 5
OPTIONS["mental"][4].label   // "不安定"
```

### なぜ `value` と `label` を分けるのか

**人間が読むもの (`label`) と、機械が計算に使うもの (`value`) を分ける** ためです。

- 画面には「とても良い」と表示したい → `label`
- グラフを描くには数値が必要 → `value`
- Excel に書き出すときは両方欲しい → 両方

実際、Excel 書き出しの処理では両方を並べて出力しています。

```js
// app.js の buildExportRows より
return [
  date,
  labelOf("condition", e.condition),   // "とても良い"
  e.condition,                          // 5
  labelOf("mental", e.mental),
  e.mental,
  // ...
];
```

ラベル列とスコア列の両方があるので、Excel を開いた人は読みやすく、グラフも作れる。
`value` と `label` を分けた設計が、そのまま最終成果物の使いやすさになっています。

### ラベルを引く関数

数値からラベルを逆引きするのが `labelOf` です。

```js
function labelOf(field, value) {
  const opt = OPTIONS[field].find((o) => o.value === Number(value));
  return opt ? opt.label : "";
}

labelOf("condition", 5)   // "とても良い"
labelOf("mental", 1)      // "不安定"
labelOf("condition", 99)  // ""  ← 見つからなければ空文字
```

`find` は「条件に合う最初の1個を探す」配列メソッドです。第10章で詳しく扱います。
`opt ? opt.label : ""` は **三項演算子** で、第5章で扱います。

## 3-4. `entries` ― なぜ配列ではなくオブジェクトなのか

記録全体を保持する `entries` は、こういう形をしています。

```js
{
  "2026-09-14": { date: "2026-09-14", condition: 3, mental: 4, ... },
  "2026-09-15": { date: "2026-09-15", condition: 5, mental: 5, ... },
  "2026-09-16": { date: "2026-09-16", condition: 4, mental: 3, ... }
}
```

**日付をキーにしたオブジェクト** です。一見すると配列のほうが自然に見えます。

```js
// もし配列だったら
[
  { date: "2026-09-14", condition: 3, ... },
  { date: "2026-09-15", condition: 5, ... },
]
```

なぜオブジェクトを選んだのでしょうか。README にヒントがあります。

> 1日1件。同じ日付で保存すると上書きされます

**「1日1件」という仕様を、データ構造そのもので保証している** のです。比べてみましょう。

| やりたいこと | オブジェクト版 | 配列版 |
| --- | --- | --- |
| その日の記録を取る | `entries["2026-09-16"]` | `list.find(e => e.date === "2026-09-16")` |
| 保存 (無ければ追加・あれば上書き) | `entries[date] = entry` | 探して、あれば置換、なければ push |
| 削除 | `delete entries[date]` | `findIndex` して `splice` |
| 同じ日付が2件できる事故 | **構造的に起こりえない** | 実装をミスると起こる |

オブジェクトなら全部1行です。しかも「同じ日付が2件」というバグが **原理的に発生しません**。

実際のコードを見てください。驚くほど短いはずです。

```js
// 保存
entries[entry.date] = entry;

// 削除
delete entries[date];

// その日の記録があるか
const exists = Boolean(entries[dateInput.value]);
```

> **設計の教訓**: 「どういうデータ構造にするか」を最初に考えると、後の処理が劇的に簡単になります。
> 逆に構造を間違えると、あちこちで複雑なコードを書くはめになります。
> プログラミングで一番効くのは、賢いアルゴリズムより **適切なデータ構造** です。

### キーの一覧を取り出す

オブジェクトのキーを配列として取り出すには `Object.keys()` を使います。

```js
Object.keys(entries)          // ["2026-09-14", "2026-09-15", "2026-09-16"]
Object.keys(entries).length   // 3  ← 記録の件数
```

`app.js` でも件数の判定に使われています。

```js
if (!Object.keys(entries).length) {
  flash("書き出す記録がありません。", true);
  return;
}
```

仲間として `Object.values()` (値の配列)、`Object.entries()` (キーと値のペアの配列) もあります。

## 3-5. スプレッド構文 `...`

オブジェクトや配列を「展開」する記法です。

### コピーを作る

```js
const backup = { ...entries };   // entries の中身をそのまま持つ、別のオブジェクト
```

なぜコピーが要るのでしょうか。「すべて削除」の処理を見てください。

```js
const backup = { ...entries };    // ① まずコピーを取る
entries = {};                     // ② 空にする
if (!persistEntries()) {          // ③ 保存を試みる
  entries = backup;               // ④ 失敗したらコピーから戻す
  flashSaveError();
  return;
}
```

保存に失敗したときに元に戻せるよう、**バックアップを取ってから危険な操作をしている** のです。
もし `const backup = entries;` と書いていたら、それは同じオブジェクトを指す別名にすぎず、
バックアップになりません。ここは重要なので節を改めます。

### 結合する

```js
return {
  date,
  ...scores,        // scores の中身 (condition, mental, ...) をここに展開
  sleepHours,
  memo,
  updatedAt,
};
```

`scores` が `{ condition: 5, mental: 4, ... }` なら、結果は
`{ date: "...", condition: 5, mental: 4, ..., sleepHours: 7.5, memo: "", updatedAt: "..." }` になります。

なお `date,` は `date: date,` の省略記法です (**ショートハンドプロパティ**)。
変数名とキー名が同じときだけ使えます。

## 3-6. 参照 ― オブジェクトは「実体」ではなく「住所」

初学者が最もハマるポイントです。

```js
// 数値や文字列 (プリミティブ) → 値そのものがコピーされる
let a = 5;
let b = a;
b = 10;
console.log(a);   // 5  ← a は影響を受けない

// オブジェクト → 「住所」がコピーされる
const x = { count: 5 };
const y = x;
y.count = 10;
console.log(x.count);   // 10 ← x も変わってしまった！
```

`const y = x;` は、**同じオブジェクトを指す2つ目の名札を付けただけ** です。中身は1つしかありません。

だから本当のコピーを作りたいときは、スプレッド構文が必要です。

```js
const y = { ...x };   // 中身を写した、別のオブジェクト
y.count = 10;
console.log(x.count); // 5  ← 今度は影響なし
```

`app.js` の削除処理も、この理解の上で書かれています。

```js
const prev = existed ? { ...entries[entry.date] } : null;   // ← コピーを取る
entries[entry.date] = entry;
if (!persistEntries()) {
  if (prev) entries[entry.date] = prev;   // ← コピーから復元
  else delete entries[entry.date];
  showError("保存に失敗しました。...");
  return;
}
```

> **注意**: スプレッド構文のコピーは **浅いコピー (shallow copy)** です。
> 1階層目はコピーされますが、中に入れ子のオブジェクトがあると、それは共有されたままです。
> `entries` の各記録は入れ子を持たないフラットな構造なので、この方法で問題ありません。
> **フラットなデータ構造にしておくと扱いが簡単になる**、というのもここでの学びです。

## 3-7. 分割代入

オブジェクトや配列から、まとめて変数を取り出す書き方です。

```js
// app.js より
const [y, m, d] = iso.split("-").map(Number);
```

1行で3つのことをやっています。

```js
const iso = "2026-09-16";
iso.split("-")              // ["2026", "09", "16"]   文字列を "-" で分割
   .map(Number)             // [2026, 9, 16]          各要素を数値に変換
const [y, m, d] = ...       // y=2026, m=9, d=16      順に取り出す
```

オブジェクトからも取り出せます。

```js
const pad = { l: 28, r: 8, t: 12, b: 22 };
const { l, r } = pad;   // l = 28, r = 8
```

分割代入を使わないと、こう書くことになります。

```js
const parts = iso.split("-").map(Number);
const y = parts[0];
const m = parts[1];
const d = parts[2];
```

4行が1行になりました。慣れると読みやすくなるので、少しずつ使ってみてください。

## まとめ

- 配列 `[ ]` は順番のリスト、オブジェクト `{ }` は名前付きの箱
- キーが変数のときは **ブラケット記法** `obj[key]` を使う
- `OPTIONS` は「オブジェクト → 配列 → オブジェクト」の入れ子。外から順に読む
- `entries` を **日付キーのオブジェクト** にすることで「1日1件」を構造で保証している
- オブジェクトの代入は **住所のコピー**。本当のコピーは `{ ...obj }`
- 適切なデータ構造は、その後のすべてのコードを簡単にする

次章は、処理をまとめて名前をつける「関数」です。
