# 第4章 関数 ― 処理に名前をつける

## この章のゴール

- 関数宣言とアロー関数を書き分けられる
- 引数・戻り値・`return` の意味が分かる
- 「1つの関数は1つの仕事」という原則を、実コードで確認できる
- スコープ (変数が見える範囲) を理解する

---

## 4-1. 関数とは

**処理のまとまりに名前をつけて、何度でも呼び出せるようにしたもの** です。

```js
function todayString() {
  const d = new Date();
  const y = d.getFullYear();
  const m = String(d.getMonth() + 1).padStart(2, "0");
  const day = String(d.getDate()).padStart(2, "0");
  return `${y}-${m}-${day}`;
}
```

使うときは名前に `()` をつけます。

```js
todayString()      // "2026-09-16"
```

`app.js` の中で `todayString()` は **7か所** から呼ばれています。
関数にしていなければ、同じ5行を7回書くことになっていました。

関数の値打ちは「短くなる」ことだけではありません。

- **名前が説明になる**: `todayString()` を見れば、中身を読まなくても何が返るか分かる
- **直す場所が1か所**: 日付形式を変えたくなったら、関数の中だけ直せばよい
- **テストしやすい**: 関数単位で「入力 → 期待する出力」を確認できる

## 4-2. 引数と戻り値

関数は「材料を受け取って、結果を返す機械」と考えると分かりやすいです。

```js
function formatHours(h) {        // h が引数 (受け取る材料)
  if (h === null || h === undefined || h === "") return "";
  return `${h}時間`;              // return が戻り値 (返す結果)
}

formatHours(7.5)    // "7.5時間"
formatHours(null)   // ""
```

引数は複数取れます。

```js
function labelOf(field, value) {
  const opt = OPTIONS[field].find((o) => o.value === Number(value));
  return opt ? opt.label : "";
}

labelOf("condition", 5)   // "とても良い"
```

引数の名前 (`field`, `value`) は **その関数の中だけで通じる仮の名前** です。
呼ぶ側がどんな変数名を使っていても関係ありません。

### `return` の2つの働き

`return` には2つの意味があります。

1. **値を返す**
2. **そこで関数を終わらせる**

2つ目が重要です。`scoreValue` を見てください。

```js
function scoreValue(v) {
  const n = Number(v);
  if (!Number.isInteger(n) || n < 1 || n > 5) return null;   // ← ここで終わる
  return n;                                                   // ← 上を通過したときだけ実行される
}
```

条件に当てはまったら `return null;` で即座に終了し、下の行は実行されません。
このように **「ダメな場合を先に弾いて、早めに return する」** 書き方を
**早期リターン (early return)** と呼びます。

早期リターンを使わないとこうなります。

```js
// 読みにくい例
function scoreValue(v) {
  const n = Number(v);
  if (Number.isInteger(n) && n >= 1 && n <= 5) {
    return n;
  } else {
    return null;
  }
}
```

条件が増えるほど、`if` の入れ子が深くなっていきます。早期リターンなら、ネストは深くなりません。
`app.js` の `normalizeEntry` は、早期リターンの見本です。

```js
function normalizeEntry(date, raw) {
  if (!DATE_RE.test(date) || !raw || typeof raw !== "object") return null;   // 弾く
  const scores = {};
  for (const field of SCORE_FIELDS) {
    const s = scoreValue(raw[field]);
    if (s === null) return null;                                              // 弾く
    scores[field] = s;
  }
  const sleepHours = parseSleepHours(raw.sleepHours);
  if (sleepHours === null) return null;                                       // 弾く
  // ここまで来たら、すべて正しいデータ
  // ... 組み立てて return
}
```

### `return` がない関数

すべての関数が値を返すわけではありません。

```js
function showError(msg) {
  formError.textContent = msg;
  formError.hidden = false;
}
```

この関数は画面を書き換えるのが仕事で、返す値はありません (正確には `undefined` が返ります)。
こういう「何かを実行するのが目的」の関数も普通です。

`app.js` の関数を役割で分けてみると、はっきり2種類に分かれます。

| 種類 | 例 | 特徴 |
| --- | --- | --- |
| **値を計算して返す** | `todayString`, `labelOf`, `scoreValue`, `computeStreak`, `buildExportRows` | 画面に触らない。同じ引数なら同じ結果 (テストしやすい) |
| **画面や保存を操作する** | `renderList`, `showError`, `fillForm`, `flash` | 戻り値がない。副作用が目的 |

この2つを混ぜないことが、読みやすいコードのコツです。

## 4-3. アロー関数

もう1つの関数の書き方です。

```js
// 関数宣言
function labelOf(field, value) {
  return "...";
}

// アロー関数 (同じ意味)
const labelOf = (field, value) => {
  return "...";
};

// 中身が return 1行だけなら、さらに短縮できる
const labelOf = (field, value) => "...";
```

`app.js` の1行目近くにある `$` は、アロー関数の短縮形の好例です。

```js
const $ = (id) => document.getElementById(id);
```

これで `$("date")` と書けば `document.getElementById("date")` と同じ意味になります。
30文字が7文字になりました。`app.js` の中で `$(...)` は **27回** 使われています。

> **`$` という名前について**: 記号ですが、JavaScript では `$` と `_` は変数名に使えます。
> jQuery というライブラリが `$` を使っていた歴史から、「要素を取ってくるもの」の慣用名になっています。

### どちらを使うべきか

初学者のうちは次の目安で十分です。

| 場面 | おすすめ |
| --- | --- |
| 短い処理、コールバックとして渡す関数 | アロー関数 |
| 名前をつけてまとまった処理を定義する | `function` 宣言 |

`app.js` もこの方針です。名前のある処理は `function`、`map` や `addEventListener` に渡す
その場限りの短い処理はアロー関数、と使い分けられています。

```js
// コールバックとしてのアロー関数
$("export-btn").addEventListener("click", exportExcel);
$("today-btn").addEventListener("click", () => {
  const next = todayString();
  if (dateInput.value === next) return;
  // ...
});

const sortedMonths = [...months].sort((a, b) => (a < b ? 1 : -1));
```

> **本当の違い**: アロー関数と `function` は `this` の扱いが違います。
> ただし `app.js` は `this` を使わない書き方なので、この教材では踏み込みません。
> 「そういう違いがある」とだけ覚えておいてください。

## 4-4. 関数は「1つの仕事」だけをする

良い関数の条件は **小さくて、名前どおりの仕事だけをする** ことです。
`app.js` の関数を並べてみましょう。名前を見るだけで役割が分かります。

```js
function todayString()          // 今日の日付を "YYYY-MM-DD" で返す
function addDays(iso, delta)    // 日付を delta 日ずらして返す
function labelOf(field, value)  // スコアからラベルを引く
function formatDateJa(iso)      // "2026-09-16" → "9/16 (水)"
function formatHours(h)         // 7.5 → "7.5時間"
function scoreValue(v)          // 1〜5 の整数なら返す、違えば null
function parseSleepHours(v)     // 0〜24 の数値なら返す、違えば null
function validate()             // フォームを検査して、正しければ記録オブジェクトを返す
function renderList()           // 記録一覧を画面に描き直す
function computeStreak()        // 今日から何日連続で記録があるか数える
function exportExcel()          // Excel ファイルを作ってダウンロードさせる
```

ここで `computeStreak` を読んでみましょう。8行で「連続記録日数」を求めています。

```js
function computeStreak() {
  let streak = 0;
  let day = todayString();
  while (entries[day]) {     // その日の記録がある限り
    streak += 1;             // 数を増やして
    day = addDays(day, -1);  // 1日前に戻る
  }
  return streak;
}
```

注目してほしいのは、この関数が **`todayString` と `addDays` を呼んでいる** ことです。
小さな関数を組み合わせて、大きな仕事をしています。

`addDays` も見てみましょう。

```js
function addDays(iso, delta) {
  const [y, m, d] = iso.split("-").map(Number);
  const dt = new Date(y, m - 1, d);
  dt.setDate(dt.getDate() + delta);       // ← 月をまたぐ計算を Date に任せている
  const yy = dt.getFullYear();
  const mm = String(dt.getMonth() + 1).padStart(2, "0");
  const dd = String(dt.getDate()).padStart(2, "0");
  return `${yy}-${mm}-${dd}`;
}

addDays("2026-09-16", -1)   // "2026-09-15"
addDays("2026-03-01", -1)   // "2026-02-28"  ← 月をまたいでも正しい
addDays("2024-03-01", -1)   // "2024-02-29"  ← うるう年も正しい
```

`setDate(0)` のような一見おかしな値を渡しても `Date` が正しく前月末に繰り下げてくれるので、
「月末は31日？30日？2月は？うるう年は？」という面倒な判定を **自分で書かずに済んでいます**。

> **教訓**: 日付・時刻・文字コード・タイムゾーンは、自力で計算せず標準の仕組みに任せる。
> 素人が書くと必ずどこかでバグります。

## 4-5. スコープ ― 変数が見える範囲

変数には「どこから見えるか」という範囲があります。

```js
function example() {
  const inside = "中だけ";
  console.log(inside);   // OK
}
console.log(inside);     // ReferenceError: inside is not defined
```

`const` / `let` で作った変数は、**それを囲む一番内側の `{ }` の中だけ** で見えます。
これを **ブロックスコープ** と言います。

```js
for (const field of SCORE_FIELDS) {
  const select = $(SELECT_IDS[field]);   // ループの中だけの変数
  // ...
}
console.log(select);   // エラー。ループの外からは見えない
```

### 外側の変数は中から見える

逆に、**内側から外側は見えます**。

```js
const STORAGE_KEY = "taichou-kiroku:v1";     // ファイル全体で見える

function saveEntries(entries) {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(entries));   // ← 外の変数が使える
}
```

`app.js` の `entries` や `dateInput` は、ファイルの上のほうで定義されているので、
どの関数からも使えます。これは便利な反面、**どの関数がどの変数を書き換えるか追いにくくなる** という
弱点もあります。規模が大きくなると、引数として渡す設計に切り替えていくことになります。

### 引数は「関数の中だけの変数」

紛らわしい例を見てください。

```js
let entries = normalizeStore(loadedRaw);    // ← 外側の entries

function saveEntries(entries) {             // ← 引数の entries (別物！)
  localStorage.setItem(STORAGE_KEY, JSON.stringify(entries));
}

function persistEntries() {
  try {
    saveEntries(entries);   // ← 外側の entries を渡している
    return true;
  } catch (e) {
    return false;
  }
}
```

`saveEntries` の中の `entries` は引数です。同じ名前ですが、外側の変数とは別物で、
**引数が外側の変数を隠しています (シャドーイング)**。

この場合は「渡されたものを保存する」という素直な関数になっているので問題ありませんが、
一般には紛らわしいので、名前を変えるほうが親切です。

## 4-6. 関数を呼ぶ・関数を渡す

`()` をつけると **実行**、つけないと **関数そのもの** を意味します。

```js
todayString     // 関数そのもの (function todayString() {...})
todayString()   // 実行した結果 ("2026-09-16")
```

この違いが効くのがイベント登録です。

```js
$("export-btn").addEventListener("click", exportExcel);    // ○ 正しい
$("export-btn").addEventListener("click", exportExcel());  // × 間違い
```

正しいほうは「クリックされたら `exportExcel` を実行して」と **関数を預けています**。
間違いのほうは **今すぐ実行して、その結果 (undefined) を預けて** しまっています。
ページを開いた瞬間に Excel がダウンロードされ、その後はボタンを押しても何も起きません。

このように「関数を値として渡す」ことができるのが JavaScript の大きな特徴で、
渡される側の関数を **コールバック関数** と呼びます。第7章と第10章で何度も出てきます。

## まとめ

- 関数は「処理に名前をつけたもの」。呼ぶときは `()` をつける
- 引数で材料を受け取り、`return` で結果を返す
- `return` は「値を返す」と「関数を終える」の2つの働きを持つ。**早期リターン** でネストを浅く保つ
- アロー関数 `(a, b) => ...` は短い処理やコールバックに向く
- 1つの関数は1つの仕事。小さい関数を組み合わせて大きな仕事をする
- 変数は `{ }` の中だけで見える (ブロックスコープ)。内側から外側は見える
- `関数名` は関数そのもの、`関数名()` は実行結果。イベント登録では前者を渡す

次章は、判断と繰り返しです。
