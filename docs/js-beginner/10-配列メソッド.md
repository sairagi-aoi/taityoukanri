# 第10章 配列メソッド ― `map` / `filter` / `find` / `sort`

## この章のゴール

- `map` `filter` `find` `some` `sort` `join` `push` `slice` を使い分けられる
- コールバック関数の書き方に慣れる
- メソッドチェーン (`.a().b().c()`) が読める
- `sort` の比較関数の仕組みが分かる

---

## 10-1. コールバック関数のおさらい

配列メソッドの多くは、**関数を引数として受け取ります**。

```js
[1, 2, 3].map((n) => n * 2)   // [2, 4, 6]
```

`(n) => n * 2` が **コールバック関数** です。
`map` が配列の要素を1つずつ取り出して、この関数に渡してくれます。

「自分でループを回す」のではなく、「**各要素に何をするか** だけを書いて、繰り返しは任せる」。
これが配列メソッドの考え方です。

---

## 10-2. `map` ― すべてを変換する

配列の各要素を変換して、**同じ長さの新しい配列** を作ります。

```js
const [y, m, d] = iso.split("-").map(Number);
// "2026-09-16" → ["2026","09","16"] → [2026, 9, 16]
```

`map(Number)` は `map((s) => Number(s))` の省略形です。関数そのものを渡しています。

Excel 書き出しでは、記録の配列を「行の配列」に変換しています。

```js
const rows = dates.map((date) => {
  const e = entries[date];
  return [
    date,
    labelOf("condition", e.condition),
    e.condition,
    labelOf("mental", e.mental),
    e.mental,
    // ...
  ];
});
```

`dates` が10件なら `rows` も10件。**1対1で変換される** のが `map` の性質です。

### `for` で書いた場合との比較

```js
// for 版
const rows = [];
for (const date of dates) {
  const e = entries[date];
  rows.push([date, labelOf("condition", e.condition), ...]);
}

// map 版
const rows = dates.map((date) => {
  const e = entries[date];
  return [date, labelOf("condition", e.condition), ...];
});
```

`map` 版には「空の配列を用意して、push していく」という手順がありません。
**「何をするか」だけが書かれていて、「どうやるか」は隠れています。**
この差が、コードの読みやすさになります。

### インデックスも受け取れる

コールバックの第2引数にはインデックスが渡されます。

```js
// xlsx.js より
const cells = row.map((v, c) => cellXml(`${colName(c)}${r + 1}`, v, r === 0 ? 1 : 0)).join("");
```

`c` が列番号です。`colName(0)` → `"A"`、`colName(1)` → `"B"` となるので、
`A1`, `B1`, `C1`... というセル参照が組み立てられます。

グラフ描画でも使われています。

```js
const points = all
  .map((date, i) => {
    const sc = scoreValue(entries[date][s.key]);
    if (sc === null) return null;
    return `${xPos(i)},${yPos(sc)}`;
  })
  .filter(Boolean);
```

`i` が「左から何番目の日か」で、それが X 座標になります。

## 10-3. `filter` ― 条件に合うものだけ残す

```js
const keys = Object.keys(parsed).filter((k) => DATE_RE.test(k)).sort();
```

「日付の形をしたキーだけ残す」。コールバックが `true` を返した要素だけが残ります。

```js
return all.filter((d) => d.startsWith(listMonthFilter));
```

「`2026-09` で始まる日付だけ残す」。月フィルタの実装です。
`startsWith` は「その文字列で始まるか」を判定する文字列メソッドです。

### `filter(Boolean)` というイディオム

```js
.filter(Boolean)
```

これは「falsy な要素を全部取り除く」という慣用句です。
`Boolean` は関数なので、各要素が `Boolean(要素)` に渡され、`true` になったものだけ残ります。

```js
["a", null, "b", undefined, "", "c"].filter(Boolean)
// ["a", "b", "c"]
```

グラフの点の配列で、`null` (不正なスコアの日) を取り除くのに使われています。

### `map` と `filter` の違い

| | `map` | `filter` |
| --- | --- | --- |
| 結果の長さ | **元と同じ** | 元以下 |
| コールバックが返すもの | 変換後の値 | `true` / `false` |
| 目的 | 変換 | 絞り込み |

## 10-4. `find` ― 最初の1つを探す

```js
function labelOf(field, value) {
  const opt = OPTIONS[field].find((o) => o.value === Number(value));
  return opt ? opt.label : "";
}
```

条件に合う **最初の要素そのもの** を返します。見つからなければ `undefined` です。

だから `opt ? opt.label : ""` という三項演算子が必要になります。
`undefined.label` を読もうとするとエラーになるからです。

### `find` と `filter` の違い

```js
[1, 2, 3, 4].find((n) => n > 2)     // 3          ← 要素そのもの
[1, 2, 3, 4].filter((n) => n > 2)   // [3, 4]     ← 配列
[1, 2, 3, 4].find((n) => n > 99)    // undefined
[1, 2, 3, 4].filter((n) => n > 99)  // []         ← 空の配列
```

`find` は最初の1つを見つけた時点で探索をやめるので、`filter` より効率的です。
**1つだけ欲しいときは `find`** を使ってください。

## 10-5. `some` / `every` ― 真偽を判定する

```js
function isValidSelectValue(field, value) {
  return OPTIONS[field].some((o) => o.value === Number(value));
}
```

`some` は「1つでも条件に合う要素があるか」を `true` / `false` で返します。

```js
if (prev && [...monthFilterEl.options].some((o) => o.value === prev)) {
  monthFilterEl.value = prev;
  listMonthFilter = prev;
}
```

「今選ばれていた月が、新しい選択肢の中にまだ存在するか」を確認しています。
データを消して、その月の記録が1件もなくなったときに備えた処理です。

兄弟メソッドの `every` は「**すべて** が条件に合うか」を返します。

```js
[1, 2, 3].some((n) => n > 2)    // true  (3 がある)
[1, 2, 3].every((n) => n > 2)   // false (1 と 2 が条件を満たさない)
```

## 10-6. `sort` ― 並べ替える

いちばん誤解の多いメソッドです。

### 罠1: 何も渡さないと文字列として比較される

```js
[10, 9, 100].sort()   // [10, 100, 9]   ← 数値順にならない！
```

文字列として比べるので `"10" < "100" < "9"` になってしまいます。
数値を並べるなら比較関数が必須です。

```js
[10, 9, 100].sort((a, b) => a - b)   // [9, 10, 100]
```

### 罠2: 元の配列を書き換える

```js
const a = [3, 1, 2];
const b = a.sort();
console.log(a);   // [1, 2, 3]   ← a も並び替わっている！
```

`map` や `filter` が新しい配列を返すのに対し、`sort` は **元の配列を直接並べ替えます**。
元の配列を保ちたいときは、コピーしてから並べ替えます。

```js
const sortedMonths = [...months].sort((a, b) => (a < b ? 1 : -1));
```

`[...months]` でコピーを作っています (第3章のスプレッド構文)。
`months` は `Set` なので、これで配列に変換する役割も兼ねています。

### 比較関数の読み方

```js
(a, b) => 数値
```

返す値の意味はこうです。

| 戻り値 | 意味 |
| --- | --- |
| 負の数 | `a` を前に |
| 正の数 | `b` を前に |
| `0` | 順序を変えない |

`app.js` の日付ソートを読んでみましょう。

```js
function sortedDates() {
  return Object.keys(entries).sort((a, b) => (a < b ? 1 : a > b ? -1 : 0));
}
```

- `a < b` (a のほうが古い) → `1` を返す → **`b` が前に来る**
- `a > b` (a のほうが新しい) → `-1` → **`a` が前に来る**
- 等しい → `0`

つまり **新しい日付が先** (降順) になります。一覧で最新の記録が上に出るのはこのためです。

もし昇順にしたければ、`1` と `-1` を入れ替えるか、こう書けます。

```js
.sort()   // 文字列の昇順。"YYYY-MM-DD" なら日付の昇順と一致する
```

実際 `normalizeStore` では単に `.sort()` を使っています。
固定長の日付文字列なので、それで正しく昇順になるのです (第2章)。

### `reverse` ― 逆順にする

```js
const dates = sortedDates().reverse();     // 降順 → 昇順
const all = sortedDates().reverse().slice(-TREND_DAYS);
```

`sortedDates()` は新しい順なので、`reverse()` で古い順にしています。

- **Excel 書き出し**: 古い順のほうが、時系列のグラフを作りやすい
- **グラフ描画**: 左から右に時間が流れる形にしたい

`reverse` も `sort` と同じく元の配列を書き換えますが、
ここでは `sortedDates()` が毎回新しい配列を返すので問題ありません。

## 10-7. `slice` ― 一部を取り出す

```js
keys.slice(0, MAX_ENTRIES)      // 先頭から 5000 件
all.slice(-TREND_DAYS)          // 末尾から 14 件
memo.slice(0, MEMO_MAX)         // 先頭 500 文字 (文字列にも使える)
sheetName.slice(0, 31)          // Excel のシート名は31文字まで
```

`slice(開始, 終了)` は **開始以上・終了未満** を取り出します。
負の数を渡すと **末尾から数えます**。

```js
[1,2,3,4,5].slice(0, 3)   // [1, 2, 3]
[1,2,3,4,5].slice(-2)     // [4, 5]      ← 最後の2つ
[1,2,3,4,5].slice(2)      // [3, 4, 5]   ← 3番目以降
```

`all.slice(-TREND_DAYS)` は「直近14日分」を取るのに使われています。
14件未満しかなくてもエラーにならず、あるだけ返ってくるのが便利なところです。

> **`slice` と `splice` を混同しないこと**。名前が1文字違いですが、
> `slice` は元の配列を変えずに一部を返し、`splice` は元の配列から要素を削除・挿入します。

## 10-8. `join` ― 配列を文字列にする

```js
missing.join("、")              // "体調、食欲、睡眠時間"
points.join(" ")                // "28,12 50,30 72,24"  (SVG の座標列)
cells.join("")                  // XML の文字列を連結
```

`join(区切り文字)` で配列を1つの文字列にします。区切り文字を省略すると `,` になります。

SVG の折れ線は、座標を空白区切りで並べた文字列で表現します。

```js
poly.setAttribute("points", points.join(" "));
```

`map` で座標文字列の配列を作り、`join` で1本の文字列にする。
**`map` → `join` の組み合わせ** は、文字列を組み立てる定番パターンです。

## 10-9. メソッドチェーン

配列メソッドは新しい配列を返すので、`.` で繋げて書けます。

```js
const all = sortedDates().reverse().slice(-TREND_DAYS);
```

1行に3つの処理が入っています。左から順に読みます。

```
sortedDates()        全日付を新しい順に取得   ["2026-09-16", "2026-09-15", "2026-09-14"]
  .reverse()         古い順にする             ["2026-09-14", "2026-09-15", "2026-09-16"]
  .slice(-14)        直近14日分だけ残す       (14件未満ならそのまま)
```

もう1つ、もう少し長い例です。

```js
const points = all
  .map((date, i) => {
    const sc = scoreValue(entries[date][s.key]);
    if (sc === null) return null;
    return `${xPos(i)},${yPos(sc)}`;
  })
  .filter(Boolean);
```

```
all           ["2026-09-14", "2026-09-15", "2026-09-16"]
  .map(...)   ["28,60", null, "72,24"]           不正な日は null にする
  .filter(Boolean)  ["28,60", "72,24"]           null を取り除く
```

**チェーンが長くなったら改行してインデントする。** これだけで格段に読みやすくなります。

### チェーンの注意点

各段階で新しい配列が作られるので、巨大な配列では効率が落ちます。
とはいえ、数千件程度なら気にする必要はありません。
**まず読みやすく書き、遅かったら測ってから直す。** 順序を間違えないことが大切です。

## 10-10. `push` と `Set`

### `push` ― 末尾に追加

```js
const missing = [];
missing.push("日付");
missing.push(FIELD_LABELS[field]);
```

`localParts.push(local, nameBytes, data);` のように、複数まとめて追加もできます。

### `Set` ― 重複しない集合

月フィルタの選択肢を作る処理に出てきます。

```js
const months = new Set();
for (const d of sortedDates()) months.add(d.slice(0, 7));   // "2026-09-16" → "2026-09"
const sortedMonths = [...months].sort((a, b) => (a < b ? 1 : -1));
```

`Set` は **同じ値を2回入れても1つしか保持しません**。
9月の記録が20件あっても、`"2026-09"` は1つだけ入ります。

配列でやろうとすると、こう書く必要がありました。

```js
const months = [];
for (const d of sortedDates()) {
  const ym = d.slice(0, 7);
  if (!months.includes(ym)) months.push(ym);   // 重複チェックが必要
}
```

`Set` を使えば重複チェックが不要になります。**道具を知っていると短く書けます。**

`[...months]` で配列に戻しているのは、`Set` には `sort` がないからです。

## 10-11. メソッド早見表

| メソッド | 返すもの | 元の配列 | 用途 |
| --- | --- | --- | --- |
| `map(fn)` | 同じ長さの新しい配列 | 変えない | 全部を変換 |
| `filter(fn)` | 条件に合う要素の配列 | 変えない | 絞り込み |
| `find(fn)` | 最初に合った要素 / `undefined` | 変えない | 1つ探す |
| `findIndex(fn)` | 最初に合った位置 / `-1` | 変えない | 位置を探す |
| `some(fn)` | `true` / `false` | 変えない | 1つでもあるか |
| `every(fn)` | `true` / `false` | 変えない | 全部そうか |
| `sort(fn)` | 並べ替えた配列 | **変える** | 並べ替え |
| `reverse()` | 逆順の配列 | **変える** | 逆順 |
| `slice(s, e)` | 一部の新しい配列 | 変えない | 切り出し |
| `join(sep)` | 文字列 | 変えない | 連結 |
| `push(v)` | 新しい長さ | **変える** | 末尾に追加 |
| `includes(v)` | `true` / `false` | 変えない | 含むか |
| `reduce(fn, init)` | 累積した1つの値 | 変えない | 集計 |

**「元の配列を変えるかどうか」** が最重要です。`sort` `reverse` `push` `splice` は変えます。

### `reduce` ― 参考

`app.js` には出てきませんが、`xlsx.js` に1か所あります。

```js
const centralSize = centralParts.reduce((s, p) => s + p.length, 0);
```

「各パーツの長さを合計する」処理です。

```js
reduce((累積値, 要素) => 新しい累積値, 初期値)
```

```js
[1, 2, 3].reduce((sum, n) => sum + n, 0)
// 0 + 1 = 1
// 1 + 2 = 3
// 3 + 3 = 6  → 6
```

最初は難しく感じますが、「集計」に使うものだと覚えておけば十分です。

## まとめ

- `map` は変換、`filter` は絞り込み、`find` は1つ探す、`some` は存在確認
- **`sort` と `reverse` と `push` は元の配列を変える**。それ以外は新しい配列を返す
- `sort` は比較関数を渡さないと文字列比較になる。数値なら `(a, b) => a - b`
- `slice(-n)` で末尾から n 件。`join(sep)` で配列を文字列に
- `map` → `join` は文字列組み立ての定番
- チェーンは改行してインデントすると読みやすい
- `Set` を使うと重複チェックのコードが不要になる

次章は、エラーへの備えと堅牢なコードの書き方です。
