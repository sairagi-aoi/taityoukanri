# 第12章 発展トピック ― IIFE・SVG・ファイル生成

## この章のゴール

- IIFE と `"use strict"` の意味が分かる

## 12-1. IIFE ― 即時実行関数式

`app.js` の全体は、こういう形で囲まれています。

```js
(function () {
  "use strict";
  // ... 全部のコード
})();
```

これは **IIFE (Immediately Invoked Function Expression / 即時実行関数式)** と呼ばれます。
「関数を定義して、その場ですぐ実行する」という書き方です。

```js
(function () { ... })();
 ↑ 関数を作り        ↑ すぐ実行
```

### なぜこうするのか

第4章で学んだスコープを思い出してください。
**関数の中で `const` / `let` で作った変数は、外から見えません。**

もし IIFE で囲まなければ、`entries` や `todayString` は
**グローバル (どこからでも見える場所)** に置かれます。すると:

- 他のスクリプトが同じ名前を使っていたら、上書きし合って壊れる
- ブラウザの拡張機能や広告スクリプトと衝突する可能性がある
- 何がどこから触られるか分からなくなる

IIFE で囲めば、中身は完全に隔離されます。
これが第0章の「Console で `todayString` と打つとエラーになる」の答えです。

```js
todayString   // Uncaught ReferenceError: todayString is not defined
```

外からは見えないのです。これは不便ではなく、**意図した安全性** です。

### `xlsx.js` のパターン

`xlsx.js` はもう少し凝った形をしています。

```js
(function (root, factory) {
  if (typeof module === "object" && module.exports) {
    module.exports = factory();     // Node.js の場合
  } else {
    root.XlsxWriter = factory();    // ブラウザの場合
  }
})(typeof self !== "undefined" ? self : this, function () {
  "use strict";
  // ... 中身
  return { build, buildBytes, crc32, colName };   // 公開するものだけ返す
});
```

これは **UMD (Universal Module Definition)** と呼ばれるパターンで、
「ブラウザでも Node.js でも使えるようにする」ための工夫です。

注目してほしいのは最後の行です。

```js
return { build, buildBytes, crc32, colName };
```

内部には `crc32`、`utf8`、`u16`、`u32`、`dosDateTime`、`buildZip`、`esc`、`colName`、
`cellXml`、`sheetXml`、`workbookXml` など多くの関数がありますが、
**外に公開するのは4つだけ** です。

残りは内部の実装詳細として隠されています。これを **モジュールパターン** と呼び、
「公開する部分を最小にする」という設計の基本です。

だから `app.js` からは `XlsxWriter.build(...)` としか呼べません。
内部をいじられる心配がなく、内部の実装を自由に変えられます。

### 今どきの書き方

現代の JavaScript には `import` / `export` という正式なモジュール機能があります。

```js
// utils.js
export function todayString() { ... }

// app.js
import { todayString } from "./utils.js";
```

ただしこれを使うには `<script type="module">` が必要で、
**ローカルファイル (`file://`) では動きません** (サーバーが要ります)。

このアプリは「`index.html` をダブルクリックするだけで動く」ことを最優先にしているので、
あえて IIFE を選んでいます。**制約から設計が決まる** 好例です。

## 12-2. `"use strict"`

```js
(function () {
  "use strict";
```

「厳格モード」を有効にする宣言です。JavaScript の緩すぎる挙動を禁止します。

```js
// 非 strict モード
function f() {
  x = 10;   // 変数宣言を忘れたのに、勝手にグローバル変数が作られる！
}

// strict モード
function f() {
  "use strict";
  x = 10;   // ReferenceError: x is not defined
}
```

タイプミスを **エラーとして教えてくれる** のが最大の利点です。

```js
const dateInput = ...;
dateInpt.value = "...";   // strict なら即エラー。非 strict でも ReferenceError だが、
                          // 代入の場合は非 strict だと黙って新しい変数が作られる
```

他にも、`delete` できないものを消そうとするとエラーになる、
重複した引数名が禁止されるなど、いくつもの安全策が入ります。

**新しく書くコードでは必ず付けてください。** デメリットはありません。

## 12-3. SVG で折れ線グラフを描く

`renderTrendsChart` は、外部ライブラリなしでグラフを描いています。
グラフ描画は難しそうに見えますが、やっていることは **座標の計算** だけです。

### SVG とは

SVG は「図形を XML で書く」画像形式です。HTML の中に直接書けます。

```html
<svg id="trends-chart" viewBox="0 0 320 120" width="100%" height="120"></svg>
```

`viewBox="0 0 320 120"` は「左上 (0,0) から幅320・高さ120の座標系で描く」という宣言です。
実際の表示サイズ (`width="100%"`) とは独立しているので、
**どんな画面幅でも自動で拡大縮小されます**。

### 座標系の準備

```js
const w = 320;
const h = 120;
const pad = { l: 28, r: 8, t: 12, b: 22 };   // 余白 (left/right/top/bottom)
const iw = w - pad.l - pad.r;                 // 描画領域の幅 = 284
const ih = h - pad.t - pad.b;                 // 描画領域の高さ = 86
```

外枠から余白を引いて、実際に線を描く範囲を決めています。
余白は軸ラベルを置くための場所です。

### 値を座標に変換する

ここが一番の要点です。

```js
function yPos(score) {
  return pad.t + ih - ((score - 1) / 4) * ih;
}
function xPos(i) {
  return pad.l + (i / (all.length - 1)) * iw;
}
```

**`yPos`**: スコア (1〜5) を縦位置に変換します。

```
(score - 1) / 4   →  スコアを 0〜1 の割合にする
                     1 → 0.0,  3 → 0.5,  5 → 1.0
× ih              →  0〜86 の高さに
pad.t + ih - ...  →  上下を反転する
```

なぜ反転が必要なのでしょう。
**画面の座標系は、下に行くほど Y が大きくなります** (数学のグラフと逆)。
スコアが高いほど上に描きたいので、引き算で反転させています。

計算してみましょう。

```
yPos(1) = 12 + 86 - 0     = 98   (一番下)
yPos(3) = 12 + 86 - 43    = 55   (真ん中)
yPos(5) = 12 + 86 - 86    = 12   (一番上)
```

**`xPos`**: 何番目の日かを横位置に変換します。

```
i / (all.length - 1)   →  0番目 = 0.0、最後 = 1.0
× iw + pad.l           →  28 〜 312 の範囲に
```

14日分なら `all.length - 1` は 13。`i` が 0〜13 なので、きれいに等間隔になります。

> **`- 1` の意味**: 14個の点を等間隔に並べると、間隔は13個です。
> `i / 14` にすると最後の点が右端に届きません。よくある off-by-one の罠です。

### 目盛り線を描く

```js
for (let level = 1; level <= 5; level++) {
  const y = yPos(level);
  const line = document.createElementNS("http://www.w3.org/2000/svg", "line");
  line.setAttribute("x1", String(pad.l));
  line.setAttribute("x2", String(w - pad.r));
  line.setAttribute("y1", String(y));
  line.setAttribute("y2", String(y));
  line.setAttribute("class", "trend-grid");
  trendsSvg.appendChild(line);
}
```

`createElementNS` は「名前空間 (namespace) 付きで要素を作る」メソッドです。
**SVG の要素は `createElement` では作れません。** 必ず `createElementNS` を使います。

```js
document.createElement("line")                                    // ✗ 動かない
document.createElementNS("http://www.w3.org/2000/svg", "line")    // ✓
```

これは覚えておかないと必ずハマるポイントです。

### 折れ線を描く

```js
for (const s of series) {
  const points = all
    .map((date, i) => {
      const sc = scoreValue(entries[date][s.key]);
      if (sc === null) return null;
      return `${xPos(i)},${yPos(sc)}`;
    })
    .filter(Boolean);
  if (points.length < 2) continue;      // 点が1個では線にならない

  const poly = document.createElementNS("http://www.w3.org/2000/svg", "polyline");
  poly.setAttribute("fill", "none");
  poly.setAttribute("stroke", s.stroke);
  poly.setAttribute("stroke-width", "2");
  poly.setAttribute("points", points.join(" "));
  trendsSvg.appendChild(poly);
}
```

`<polyline>` は「点を順に結んだ折れ線」です。
`points` 属性に `"28,60 50,30 72,24"` のような座標の羅列を渡します。

第10章で見た `map` → `filter(Boolean)` → `join(" ")` の組み合わせが、
ここで実際に使われています。

### 色を CSS 変数で指定する

```js
const series = [
  { key: "condition", stroke: "var(--level-5)", label: "体調" },
  { key: "mental", stroke: "var(--accent)", label: "メンタル" },
];
```

`stroke` (線の色) に `var(--level-5)` という CSS のカスタムプロパティを指定しています。
第6章で見た「見た目は CSS に任せる」の実践です。

`style.css` にはダークモード用の定義があるので、
**ダークモードに切り替えるとグラフの色も自動で変わります**。JavaScript は何も知りません。

### アクセシビリティへの配慮

```js
const title = document.createElementNS("http://www.w3.org/2000/svg", "title");
title.textContent = `直近${all.length}日の体調・メンタル (1〜5)`;
trendsSvg.appendChild(title);
```

`<title>` 要素を入れると、SVG にホバーしたときのツールチップになり、
支援技術にも内容が伝わります。

## 12-4. ファイルをダウンロードさせる

```js
function exportExcel() {
  if (!Object.keys(entries).length) {
    flash("書き出す記録がありません。", true);
    return;
  }
  const rows = buildExportRows();
  const blob = XlsxWriter.build({ sheetName: "体調記録", rows, colWidths: [...] });

  const url = URL.createObjectURL(blob);              // ① Blob への一時 URL を作る
  const a = document.createElement("a");              // ② <a> タグを作る
  a.href = url;
  a.download = `体調記録_${todayString()}.xlsx`;      // ③ ダウンロード指定
  document.body.appendChild(a);
  a.click();                                          // ④ プログラムからクリック
  a.remove();                                         // ⑤ 片付け
  setTimeout(() => URL.revokeObjectURL(url), 1000);   // ⑥ URL を解放
  flash(`${rows.length - 1}件をExcelファイルに書き出しました。`);
}
```

これは **「見えないリンクを作って、自分でクリックする」** という定番の技です。

### `Blob` とは

**Binary Large Object** の略で、「ファイルの中身そのもの」を表すオブジェクトです。

```js
new Blob([バイト列], { type: "MIMEタイプ" })
```

`xlsx.js` の最後で作られています。

```js
function build(opts) {
  return new Blob([buildBytes(opts)], {
    type: "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
  });
}
```

この長い `type` が「これは Excel ファイルです」という宣言です。

### `URL.createObjectURL`

Blob に一時的な URL を割り当てます。

```js
URL.createObjectURL(blob)
// "blob:http://localhost/8f3a2b1c-..."
```

この URL は **そのページの中でだけ有効** で、リロードすると無効になります。

### `a.download` 属性

`<a download="ファイル名">` を付けると、ブラウザは「移動」ではなく「保存」をします。

```js
a.download = `体調記録_${todayString()}.xlsx`;   // "体調記録_2026-09-16.xlsx"
```

### `revokeObjectURL` を忘れない

```js
setTimeout(() => URL.revokeObjectURL(url), 1000);
```

`createObjectURL` で作った URL は、明示的に解放するまでメモリを占有し続けます。
`revokeObjectURL` で解放するのですが、**すぐ解放するとダウンロードが失敗する** ことがあるので、
1秒の猶予を置いています (第7章)。

## 12-5. `.xlsx` の正体は ZIP + XML

`xlsx.js` は約 10KB で、外部ライブラリなしに Excel ファイルを作っています。
なぜそんなことが可能なのでしょうか。

**`.xlsx` は、XML ファイルを何個か ZIP で固めたものだからです。**

### 試してみる

書き出した `.xlsx` の拡張子を `.zip` に変えて展開してみてください。
中からこんなファイルが出てきます。

```
[Content_Types].xml          ← 中に何が入っているかの目録
_rels/.rels                  ← ルートの関係定義
xl/workbook.xml              ← ブック全体 (シートの一覧)
xl/_rels/workbook.xml.rels   ← ブックとシートの関係定義
xl/styles.xml                ← 書式 (フォント・色)
xl/worksheets/sheet1.xml     ← シートの中身 (セルのデータ)
```

`xlsx.js` は、この6つのファイルを文字列として組み立て、ZIP に詰めているだけです。

```js
function buildBytes(opts) {
  const sheetName = (opts.sheetName || "Sheet1").slice(0, 31);
  const files = [
    { name: "[Content_Types].xml", data: CONTENT_TYPES },
    { name: "_rels/.rels", data: ROOT_RELS },
    { name: "xl/workbook.xml", data: workbookXml(sheetName) },
    { name: "xl/_rels/workbook.xml.rels", data: WORKBOOK_RELS },
    { name: "xl/styles.xml", data: STYLES },
    { name: "xl/worksheets/sheet1.xml", data: sheetXml(opts.rows, opts.colWidths) },
  ];
  return buildZip(files);
}
```

### セルの XML

```js
function cellXml(ref, value, styleId) {
  const s = styleId ? ` s="${styleId}"` : "";
  if (value === null || value === undefined || value === "") {
    return styleId ? `<c r="${ref}"${s}/>` : "";
  }
  if (typeof value === "number" && Number.isFinite(value)) {
    return `<c r="${ref}"${s}><v>${value}</v></c>`;          // 数値セル
  }
  return `<c r="${ref}" t="inlineStr"${s}><is><t xml:space="preserve">${esc(value)}</t></is></c>`;  // 文字列セル
}
```

`<c r="A1">` の `r` は「セル参照」です。`A1`, `B1`, `C2`... という Excel のあの表記です。

重要なのは **数値と文字列を区別している** ことです。

- 数値 → `<v>5</v>` … Excel で計算やグラフに使える
- 文字列 → `<is><t>とても良い</t></is>` … 文字として扱われる

第3章で見た「`value` と `label` を両方出力する」設計が、ここで活きています。
ラベル列は文字列セル、スコア列は数値セルになるので、
**Excel を開いてスコア列を選ぶだけでグラフが作れます**。

### XML エスケープ

```js
function esc(s) {
  return String(s)
    .replace(/[\x00-\x08\x0B\x0C\x0E-\x1F]/g, "")   // 制御文字を除去
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;");
}
```

メモに `<` や `&` が入っていると XML が壊れるので、安全な表記に変換しています。
第6章の XSS 対策と同じ考え方です。

> **順序に注意**: `&` を最初に置換しないと、`<` → `&lt;` の `&` がさらに `&amp;` にされて
> `&amp;lt;` になってしまいます。**`&` を必ず最初に。** 定番の落とし穴です。

### 列名の変換

```js
function colName(idx) {
  // 0 -> A, 25 -> Z, 26 -> AA
  let s = "";
  idx += 1;
  while (idx > 0) {
    const m = (idx - 1) % 26;
    s = String.fromCharCode(65 + m) + s;
    idx = Math.floor((idx - 1) / 26);
  }
  return s;
}
```

`String.fromCharCode(65)` は `"A"` です (65 は A の文字コード)。
26進数の変換ですが、`A` が 1 に対応するので、普通の26進数とは少しずれた計算になります。

### ZIP の構造

```js
const local = new Uint8Array([
  ...u32(0x04034b50),   // ローカルファイルヘッダの署名
  ...u16(20),           // 必要なバージョン
  ...u16(0x0800),       // フラグ: ファイル名は UTF-8
  ...u16(0),            // 圧縮方式: 無圧縮 (stored)
  ...u16(now.time),
  ...u16(now.date),
  ...u32(crc),          // CRC32 チェックサム
  ...u32(data.length),
  ...u32(data.length),
  ...u16(nameBytes.length),
  ...u16(0),
]);
```

ZIP は「決まった順番でバイトを並べる」フォーマットです。
`0x04034b50` という4バイトは「ここからファイルが始まる」という目印 (マジックナンバー) です。

**圧縮していない (`stored`)** ところがポイントです。
ZIP は圧縮しなくても正しい ZIP なので、圧縮アルゴリズム (Deflate) を実装せずに済みます。
ファイルサイズは大きくなりますが、**コードは劇的に簡単になります**。

`Uint8Array` は「0〜255 の数値だけを入れられる、効率のよい配列」です。
バイナリデータを扱うときの標準的な道具です。

### CRC32

```js
function crc32(bytes) {
  let c = 0xffffffff;
  for (let i = 0; i < bytes.length; i++) c = CRC_TABLE[(c ^ bytes[i]) & 0xff] ^ (c >>> 8);
  return (c ^ 0xffffffff) >>> 0;
}
```

ZIP はファイルごとに **チェックサム (壊れていないかの検査値)** を持ちます。
`^` は XOR、`>>>` は符号なし右シフトというビット演算です。

この計算の中身を理解する必要はありません。
**「ZIP の仕様がそう決めているから、そのとおりに実装した」** というだけです。

> **学び**: 仕様書どおりに実装すれば、複雑に見えるものも作れます。
> `.xlsx` も ZIP も公開された仕様 (ECMA-376、APPNOTE.TXT) があります。
> **魔法はありません。** どんなソフトウェアも、誰かが仕様を読んで書いたものです。

## 12-6. この章から持ち帰ってほしいこと

1. **IIFE とモジュールパターン** … 公開する範囲を最小にするのが設計の基本
2. **グラフは座標計算** … 値を画面上の位置に変換するだけ。魔法ではない
3. **ファイル生成も可能** … ブラウザだけで `.xlsx` すら作れる
4. **仕様を読めば作れる** … ライブラリの中身も、誰かが書いたただのコード

「ライブラリがないとできない」と思っていたことの多くは、
**標準機能の組み合わせで実現できます**。もちろん実務ではライブラリを使うほうが速く安全ですが、
「中で何が起きているか」を知っているかどうかで、トラブル時の対応力がまったく変わります。

## まとめ

- **IIFE** `(function(){...})()` は変数をグローバルに漏らさないための囲い
- `"use strict"` はタイプミスをエラーにしてくれる。常に付ける
- **SVG のグラフは座標計算**。`createElementNS` を使うのを忘れない
- 画面座標は下向きが正なので、値を Y に変換するとき **反転** が必要
- `Blob` + `URL.createObjectURL` + `<a download>` でファイルを保存させられる
