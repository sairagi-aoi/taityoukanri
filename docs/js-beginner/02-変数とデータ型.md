# 第2章 変数とデータ型

## この章のゴール

- `const` と `let` を使い分けられる (`var` は使わない理由も分かる)
- 数値・文字列・真偽値・`null` / `undefined` の違いが分かる
- 「文字列の `"5"`」と「数値の `5`」を区別し、変換の必要性を説明できる
- テンプレートリテラル `` `${}` `` が使える

---

## 2-1. 変数 ― 値に名前をつける箱

プログラムは値を扱います。値に名前をつけて後から使えるようにするのが **変数** です。

```js
// app.js の冒頭より
const STORAGE_KEY = "taichou-kiroku:v1";
const MAX_ENTRIES = 5000;
const MEMO_MAX = 500;
const TREND_DAYS = 14;
```

もしこれらを変数にせず、コードの至るところに `"taichou-kiroku:v1"` や `500` を直接書いたらどうなるでしょう。

- 保存キーを変えたくなったとき、全部の箇所を探して直す必要がある (1か所でも漏れたらバグ)
- `500` という数字だけ見ても、それが何の 500 なのか読み手には分からない

`MEMO_MAX` という名前がついていれば、**コードを読むだけで「メモの最大文字数」だと分かります**。
これを「マジックナンバーを名前付き定数にする」と言います。

> **命名の慣習**: プログラム全体で変わらない設定値は `STORAGE_KEY` のように **大文字＋アンダースコア**、
> 普通の変数は `dateInput` のように **小文字始まりの camelCase (キャメルケース)** で書きます。
> これは文法上のルールではなく、読み手のための約束事です。

## 2-2. `const` と `let` の使い分け

変数を作る方法は2つあります。

```js
const STORAGE_KEY = "taichou-kiroku:v1";  // 後から入れ替えない
let listMonthFilter = "";                 // 後から入れ替える
```

| キーワード | 意味 | 使うとき |
| --- | --- | --- |
| `const` | **再代入できない** | 基本はこちら。ほとんどの変数は `const` で足りる |
| `let` | 再代入できる | 値が途中で変わる変数だけ |
| `var` | 古い書き方 | **使わない** |

`const` にしておくと、うっかり別の値を入れてしまう事故をブラウザが止めてくれます。

```js
const x = 1;
x = 2;  // Uncaught TypeError: Assignment to constant variable.
```

`app.js` の中で `let` になっているのは、次の4つだけです。

```js
let formBaseline = null;      // フォームの初期状態を覚えておく箱。入力のたびに更新される
let lastDateValue = "";       // 直前に選ばれていた日付
let listMonthFilter = "";     // 一覧で表示中の月。プルダウンを変えるたびに変わる
let entries = normalizeStore(loadedRaw);  // 記録全体。全削除時に {} に置き換わる
```

**「変わるものだけ `let`」** と決まっているので、`let` を見つけたら
「この値は途中で変わるんだな」と読み手に伝わります。これが可読性です。

### `const` の注意点 ― 中身は変えられる

ここは初学者が必ず一度つまずくところです。

```js
const entries = {};
entries["2026-09-16"] = { condition: 5 };  // ← これは OK！
entries = {};                              // ← これは エラー
```

`const` が禁止しているのは **「箱ごと入れ替えること」** であって、
**「箱の中身をいじること」** ではありません。

実際 `app.js` でも `entries` に対してこう書かれています。

```js
entries[entry.date] = entry;   // 追加・上書き
delete entries[date];          // 削除
```

では、なぜ `entries` は `const` ではなく `let` なのでしょうか。「すべて削除」の処理を見てください。

```js
const backup = { ...entries };
entries = {};                  // ← 箱ごと空のオブジェクトに入れ替えている
if (!persistEntries()) {
  entries = backup;            // ← 失敗したら元の箱に戻す
}
```

ここで **箱ごと入れ替えている** ので `let` が必要なのです。コードには理由があります。

## 2-3. データ型

JavaScript の値には種類 (型) があります。このアプリに出てくるものを押さえましょう。

### 数値 (number)

```js
const MAX_ENTRIES = 5000;
const hours = 7.5;
```

整数も小数も同じ `number` 型です。`app.js` では、体調のスコア (1〜5) や睡眠時間が数値です。

### 文字列 (string)

```js
const STORAGE_KEY = "taichou-kiroku:v1";
const label = "とても良い";
```

`"..."` `'...'` `` `...` `` のいずれかで囲みます。囲まないと変数名だと解釈されてしまいます。

### 真偽値 (boolean)

`true` か `false` の2つだけです。条件分岐の材料になります。

```js
const exists = Boolean(entries[dateInput.value]);   // 記録が既にあるか
editBadge.hidden = !exists;                          // なければ「編集中」バッジを隠す
```

`!` は「否定」です。`!true` は `false`、`!false` は `true` になります。

### `null` と `undefined`

似ていますが意味が違います。

| 値 | 意味 | たとえ |
| --- | --- | --- |
| `null` | **意図的に「無い」と入れた** | 「該当なし」と書かれた回答欄 |
| `undefined` | **まだ何も入っていない** | 白紙のままの回答欄 |

`app.js` は `null` を「不正な値だった」という合図に使っています。

```js
function scoreValue(v) {
  const n = Number(v);
  if (!Number.isInteger(n) || n < 1 || n > 5) return null;  // 不正なら null
  return n;                                                  // 正しければ数値
}
```

呼ぶ側は `null` かどうかで判断します。

```js
const s = scoreValue(raw[field]);
if (s === null) return null;   // 1つでも不正なら、この記録ごと無効にする
```

一方 `undefined` は、存在しないものを読んだときに自動的に返ってきます。

```js
const entries = { "2026-09-16": { condition: 5 } };
entries["2026-09-16"]   // { condition: 5 }
entries["2030-01-01"]   // undefined  ← エラーではない
```

### 型を調べる

Console で試してみてください。

```js
typeof 5          // "number"
typeof "5"        // "string"
typeof true       // "boolean"
typeof undefined  // "undefined"
typeof null       // "object"  ← JavaScript 初期からの有名なバグ。null は object ではありません
typeof {}         // "object"
typeof []         // "object"  ← 配列も object 扱い
typeof function(){}  // "function"
```

## 2-4. 文字列と数値の変換 ― 実務で最重要

第0章の宿題の答え合わせです。

```js
"5" + 3   // "53"   ← + は文字列結合として働いた
"5" - 3   // 2      ← - は文字列にないので、数値に変換されてから計算された
```

`+` だけが「足し算」と「文字列結合」の両方の意味を持つため、こういうことが起きます。
これは JavaScript の有名な落とし穴です。

### なぜ変換が必要なのか

**HTML のフォームから取れる値は、見た目が数字でも必ず文字列です。**

```js
// <input type="number" id="sleep-hours" value="7"> の場合
sleepHoursInput.value        // "7"  ← 文字列！
sleepHoursInput.value + 1    // "71" ← 足し算にならない
Number(sleepHoursInput.value) + 1   // 8  ← 正しい
```

だから `app.js` は、フォームから値を取るところで必ず変換しています。

```js
return {
  date: dateInput.value,                       // 日付は文字列のままでよい
  condition: Number($("condition").value),     // ← 数値に変換
  mental: Number($("mental").value),           // ← 数値に変換
  appetite: Number($("appetite").value),
  motivation: Number($("motivation").value),
  sleepHours: hours,
  sleepQuality: Number($("sleep-quality").value),
  memo: memoInput.value.trim().slice(0, MEMO_MAX),
  updatedAt: new Date().toISOString(),
};
```

逆に、`<option>` に値を設定するときは文字列に戻しています。

```js
o.value = String(opt.value);   // 数値 5 → 文字列 "5"
```

### `===` と `==` ― 必ず `===` を使う

```js
5 === "5"   // false  ← 型まで含めて比較 (厳密等価)
5 ==  "5"   // true   ← 型を勝手に変換してから比較 (等価)
```

`==` は親切なようでいて、予想外の挙動を招きます。**常に `===` (と `!==`) を使ってください。**
`app.js` でも一貫して `===` が使われています。

```js
if (s === null) return null;
if (select.value === "") { ... }
```

> **例外**: `x == null` と書くと「`x` が `null` または `undefined`」をまとめて判定できるため、
> このイディオムだけは意図的に使われることがあります。`app.js` にも登場します。
> ```js
> if (raw.memo != null && raw.memo !== "") { ... }
> ```

## 2-5. テンプレートリテラル

文字列の中に変数を埋め込む書き方です。バッククォート `` ` `` で囲み、`${変数}` と書きます。

```js
// 古い書き方
const msg = formatDateJa(entry.date) + " の記録を保存しました。";

// テンプレートリテラル (こちらを使う)
const msg = `${formatDateJa(entry.date)} の記録を保存しました。`;
```

`app.js` では日付の組み立てにも使われています。

```js
function todayString() {
  const d = new Date();
  const y = d.getFullYear();                              // 2026
  const m = String(d.getMonth() + 1).padStart(2, "0");    // "09"
  const day = String(d.getDate()).padStart(2, "0");       // "16"
  return `${y}-${m}-${day}`;                              // "2026-09-16"
}
```

この関数には学びが詰まっています。

- `d.getMonth()` は **0 から始まります**。1月が `0`、9月が `8`。だから `+ 1` が必要です。
  JavaScript の代表的な罠のひとつなので覚えておいてください。
- `padStart(2, "0")` は「2文字になるまで先頭に `0` を詰める」という意味です。
  `"9"` → `"09"`。これがないと `2026-9-16` になってしまい、`<input type="date">` が受け付けません。
- `padStart` は文字列のメソッドなので、数値に直接は使えません。だから先に `String(...)` で変換しています。

### 数値の桁揃えが必要な理由

日付を `YYYY-MM-DD` という固定長の形式で持つと、**文字列のまま並べ替えるだけで日付順になります**。

```js
"2026-09-05" < "2026-09-16"   // true
```

`app.js` はこの性質を利用して、日付のソートを驚くほど簡単に済ませています。

```js
function sortedDates() {
  return Object.keys(entries).sort((a, b) => (a < b ? 1 : a > b ? -1 : 0));
}
```

`Date` オブジェクトに変換する必要すらありません。**データの持ち方を工夫すると処理が簡単になる**、
という good example です。

## まとめ

- 基本は `const`。変わる値だけ `let`。`var` は使わない
- `const` は「入れ替え禁止」であって「中身の変更禁止」ではない
- **フォームから取れる値は必ず文字列**。数値として使うなら `Number()` で変換する
- 比較は必ず `===`
- テンプレートリテラル `` `${x}` `` で文字列を組み立てる
- 日付を `YYYY-MM-DD` 固定長にしておくと、文字列比較だけで日付順に並べられる

次章は、値を「ひとまとまり」で扱うためのオブジェクトと配列です。
